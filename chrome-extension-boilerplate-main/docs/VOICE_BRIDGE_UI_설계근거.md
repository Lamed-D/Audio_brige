# VOICE BRIDGE UI 설계 근거

## 1. 문서 목적

이 문서는 VOICE BRIDGE 크롬 확장프로그램의 Side Panel UI를 현재 구조로 선택한 이유와 접근성 원칙을 정리한다. 대상은 전맹 시각장애인, 저시력 사용자, 화면해설을 필요로 하는 일반 사용자를 포함한다.

NVDA와 센스리더는 VOICE BRIDGE가 연동해야 하는 외부 기능이 아니다. 사용자가 확장프로그램을 조작할 때 이용할 수 있는 스크린리더이므로, VOICE BRIDGE는 별도 애드온이나 전용 API 대신 표준 HTML과 브라우저 접근성 트리를 통해 호환성을 확보한다.

## 2. Side Panel을 선택한 이유

영상 페이지 위에 메뉴를 띄우는 방식은 플레이어 자막, 광고, 전체화면 버튼과 겹칠 수 있고 사이트 DOM 변경에 영향을 많이 받는다. Chrome Side Panel은 원본 영상을 가리지 않으며 다음 장점이 있다.

- 영상 페이지와 조작 영역을 분리해 화면을 가리지 않는다.
- YouTube의 DOM 구조가 바뀌어도 설정 UI는 안정적으로 유지된다.
- 키보드 포커스 순서를 확장프로그램 내부에서 통제할 수 있다.
- 스크린리더가 원본 페이지와 확장 UI를 구분해 탐색하기 쉽다.
- 분석 상태, 현재 영상, 재생 설정을 한곳에서 확인할 수 있다.

## 3. 정보 구조

Side Panel은 다음 세 영역으로 구성한다. 순서는 전맹 사용자가 화면을 위에서부터 탐색할 때의 우선순위다.

1. `화면해설`: 기능 켜기, 음량, 더킹, 자동 정지와 현재 해설 상태를 조작한다.
2. `현재 영상`: 현재 영상의 제목, 재생 상태와 위치를 확인한다.
3. `진단 정보`: 버전, 영상 ID, manifest와 segment 상태를 필요할 때만 펼쳐 확인한다.

버전·스키마·영상 ID·manifest ID는 일반 사용자의 작업에 필요하지 않으므로 기본 탐색 흐름에서 제외했다. 기능 설명용 배너나 장식 영역도 추가하지 않았다. 반복 사용자가 현재 상태를 빠르게 확인하고 바로 설정을 변경하는 작업형 UI이기 때문이다.

## 4. 컨트롤 선택 근거

### 화면해설 켜기

켜짐과 꺼짐만 존재하는 이진 설정이므로 네이티브 체크박스를 사용한다. 네이티브 요소는 키보드 Space 조작과 체크 상태 전달이 기본 제공되며, 커스텀 스위치보다 스크린리더 호환 위험이 낮다. `화면해설 사용`이라는 동작 중심 이름을 사용해 섹션 제목과 컨트롤 이름을 구분했다.

### 화면해설 음량

연속적인 값을 선택하므로 슬라이더를 사용한다. 슬라이더 옆에 현재 값을 백분율로 표시하고 `aria-valuetext`에도 동일한 값을 제공한다. 기본값은 100%이며 Offscreen Audio Engine의 실제 음량에 적용된다.

### 해설 중 원본 음량

사용자에게 내부 용어인 `duck factor` 대신 결과를 직접 설명하는 `해설 중 원본 음량`이라는 이름을 사용한다. 기본값 35%는 화면해설을 분명하게 들려주면서 원본의 배경음과 맥락을 완전히 제거하지 않는 값이다.

### 긴 해설 자동 정지

extended 해설은 대사 사이에 들어갈 수 없으므로 영상을 잠시 멈춰야 한다. 이를 원하지 않는 사용자를 위해 별도 체크박스를 제공한다. `긴 화면해설 재생 시 영상 자동 정지`라는 이름으로 결과를 직접 설명한다. 설정을 끄면 extended 해설을 원본 음성과 겹쳐 재생하지 않고 건너뛴다. 이 결과는 스크린리더 사용자에게만 연결된 숨은 설명으로도 제공한다.

### 현재 해설

재생 중인 문장을 시각적으로 확인할 수 있도록 표시한다. 다만 이 영역에는 `aria-live`를 사용하지 않는다. 화면해설 TTS가 재생되는 동안 스크린리더가 같은 문장을 다시 읽어 음성이 겹치는 것을 방지하기 위해서다.

### 조작 알림음

NVDA는 초점을 받은 네이티브 컨트롤의 이름·역할·상태를 읽고, VOICE BRIDGE는 이를 다시 말하지 않는다. 대신 Tab 초점 이동, 체크박스 변경, 슬라이더 조절에 짧은 비언어 음을 제공한다. 슬라이더 음은 값이 높을수록 음높이가 올라가므로 반복적인 퍼센트 낭독 없이도 조절 방향을 확인할 수 있다.

알림음은 짧게 유지하되 실제 사용자 피드백에 따라 기본 출력은 이전 버전보다 약 4배 높이고 기본 설정값을 80%로 정했다. 사용자는 `조작 알림음 음량` 슬라이더로 조절하거나 `조작 알림음` 체크박스로 끌 수 있다. 진동은 데스크톱 장치에서 지원 여부가 불안정하므로 기본 피드백 수단으로 사용하지 않는다.

## 5. 상태 안내 원칙

- 연결 여부와 오류는 아이콘 색상과 텍스트를 함께 사용한다.
- 재생 위치처럼 계속 변하는 값은 자동 낭독하지 않는다.
- 네이티브 컨트롤의 변경 상태는 해당 컨트롤이 직접 전달하게 한다.
- 작업 진행과 일반 결과는 `role="status"`, `aria-live="polite"`로 현재 NVDA 발화를 방해하지 않고 안내한다.
- 음성 재생 오류처럼 즉시 알아야 하는 문제는 별도 `role="alert"`, `aria-live="assertive"` 영역으로 한 번 안내한다.
- 단축키 결과와 패널 열림·닫힘은 `chrome.tts` 기반 한국어 음성으로 우선 안내한다. 사용자가 자체 음성을 끄거나 TTS 실행에 실패하면 활성 YouTube 페이지 또는 Side Panel의 ARIA 실시간 영역으로 폴백한다.
- 포커스 이동 때 컨트롤 이름을 별도 TTS로 반복하지 않고 NVDA의 기본 낭독과 짧은 초점음만 사용한다.
- 내부 모듈명이나 디버그 메시지를 사용자 안내 문구로 노출하지 않는다.

## 6. 색상 선택 근거

| 역할 | 색상 | 근거 |
| --- | --- | --- |
| 기본 배경 | `#F7F8FA` | 순백색보다 눈부심을 줄이면서 콘텐츠 표면과 구분한다. |
| 콘텐츠 표면 | `#FFFFFF` | 정보 영역의 명확한 기준면을 만든다. |
| 기본 글자 | `#111827` | 밝은 배경에서 높은 명도 대비를 확보한다. |
| 보조 글자 | `#475569` | 위계를 만들되 읽기 어려울 정도로 흐리게 만들지 않는다. |
| 주요색 | `#075985` | 브랜드 헤더와 주요 조작에 사용하며 흰색 글자와 구분된다. |
| 강조색 | `#F2C14E` | 화면해설의 존재를 나타내는 보조 신호로 제한해 사용한다. |
| 포커스 | `#005FCC` | 키보드 포커스를 명확하게 표시한다. |

노란색과 네이비만으로 전체 화면을 구성하지 않았다. 강한 색을 넓게 사용하면 저시력 사용자에게 눈부심과 피로를 줄 수 있으므로, 중립 배경과 짙은 본문색을 기본으로 하고 파란색과 노란색은 역할이 있는 위치에만 사용한다. 색상은 상태를 전달하는 유일한 수단으로 사용하지 않는다.

## 7. 레이아웃과 확대 대응

- 섹션을 카드 안에 다시 넣지 않고 전체 폭의 구분선 구조를 사용한다.
- 고정 폭 대신 가변 폭과 줄바꿈을 사용한다.
- 260px 이하에서는 메타데이터의 제목과 값을 세로로 배치한다.
- 긴 영상 ID와 manifest ID는 컨테이너 안에서 줄바꿈한다.
- 글자 크기를 화면 폭에 따라 축소하지 않는다.
- 200% 확대에서도 가로 스크롤 없이 읽고 조작할 수 있어야 한다.
- Windows 고대비 모드에서는 시스템 포커스 색상을 사용한다.

## 8. 설정 저장 원칙

사용자 설정은 manifest가 아니라 `chrome.storage.local`에 저장한다.

- 화면해설 켜기
- 화면해설 음량
- 해설 중 원본 음량
- 긴 해설 자동 정지
- 조작 알림음
- 조작 알림음 음량
- 단축키·패널 음성 안내

manifest는 영상별 해설 데이터이고 사용자 설정은 개인의 청취 선호이므로 수명과 소유권이 다르다. 두 데이터를 분리하면 백엔드 manifest가 갱신되거나 영상이 바뀌어도 사용자의 설정이 유지된다.

설정은 활성 YouTube 영상이 없어도 항상 조작하고 저장할 수 있다. 영상 연결 여부는 현재 적용 상태에만 영향을 주며 사용자의 선호 설정을 막는 조건으로 사용하지 않는다.

## 9. 검증 기준

- Tab과 Shift+Tab으로 모든 컨트롤에 순서대로 접근할 수 있다.
- 첫 번째 설정 컨트롤은 `화면해설 사용`이어야 한다.
- Space로 체크박스를 변경할 수 있다.
- 방향키로 슬라이더 값을 변경할 수 있다.
- Tab 초점 이동, 체크박스 변경, 슬라이더 조절음이 서로 구분된다.
- 조작 알림음을 끄면 이후 비언어 피드백이 재생되지 않는다.
- `Alt+Shift+J`에서 현재 시간, 남은 시간과 전체 길이가 한 번만 읽힌다.
- `Alt+Shift+H`에서 화면해설 상태가 변경되고 결과가 한 번만 읽힌다.
- 각 컨트롤의 이름, 역할, 현재 값이 접근성 트리에 노출된다.
- 360px 기본 폭과 200% 확대 조건에서 가로 넘침이 없다.
- `forced-colors` 환경에서 포커스가 사라지지 않는다.
- 화면해설 재생 중 현재 문장이 중복 자동 낭독되지 않는다.
- 재생 오류는 한 번만 긴급 우선순위로 안내된다.
- 설정 변경 후 Side Panel을 다시 열거나 페이지를 새로고침해도 값이 유지된다.
- 진단 정보는 기본적으로 접혀 있고 일반 탐색 흐름에 기술 ID가 노출되지 않는다.

## 10. POC 범위

NVDA를 이용한 키보드·레이블 검증은 무료로 수행할 수 있으므로 POC 검증에 포함한다. 센스리더는 테스트 환경을 확보할 수 있을 때 동일 항목을 확인한다. 두 제품을 위한 전용 애드온 개발이나 음성 합성 연동은 현재 범위에 포함하지 않는다.
