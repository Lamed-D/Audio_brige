# 솔루션 가설 5종

**문제정의**
> 무더위쉼터는 9만 3천 곳으로 늘었지만, 걸을 수 있는 사람은 어디인지 몰라 공항·박물관으로 흩어지고, 걸을 수 없는 사람은 집에 남아 쓰러진다.

문제정의가 **두 집단**을 담고 있으므로, 솔루션도 두 갈래로 갈린다.

- **A그룹 — 이동 가능**: 정보만 닿으면 해결됨 (미이용 사유 1위 "몰라서" 33.0%)
- **B그룹 — 이동 불가**: 쉼터가 답이 아님 (건강상 외출 곤란 6.5% + 집에서 쉬는 게 편함 3.8%)

---

## 가설 1. 라스트마일은 앱이 아니라 사람이다 ★추천

> **디지털 취약계층에게 디지털 서비스를 주는 건 모순이다.**
> 이미 매일 방문하는 돌봄 인력을 전달 채널로 삼으면, 어르신은 아무것도 하지 않아도 된다.

### 근거

- 보건복지부 「2026년 여름철 취약계층 보호대책」: 생활지원사·재난도우미가 **폭염주의보·경보 시 매일 1회, 폭염중대경보 시 매일 2회** 방문 또는 전화 안부 확인
- 이미 채널이 돌고 있다. 우리가 새로 만들 필요가 없다

### 여기서 드러나는 진짜 페인포인트

생활지원사 한 명이 담당하는 어르신은 수십 명이다. **매일 1~2회 확인해야 하는데, 오늘 누구부터 봐야 하는지 알 방법이 없다.** 지금은 순번이나 감으로 돈다.

### 서비스

**어르신용 앱이 아니라, 생활지원사용 "오늘의 우선순위 리스트"**

- 실내 온·습도 + 활동량 이상 + 개인 위험요인(연령·만성질환·냉방기 보유·건물 노후도)을 종합해 위험 점수 산출
- 매일 아침 **"오늘 이 순서로 도세요"** 제시
- 임계 초과 시 응급관리요원에게 즉시 알림
- 방문 시 **"오늘 밤 여기가 열려 있어요"** 안내 카드 동시 제공 → A그룹의 33% "몰라서"도 같은 채널로 해결

### 검증 방법

- 위험 점수 상위군과 실제 온열질환 발생의 상관 확인
- 무작위 순회 대비 위험도 순 방문의 **탐지 효율 개선폭** 시뮬레이션

### 필요 데이터

| 데이터 | 확보 |
|---|---|
| 기상청 기온·습도·폭염특보 | ⭕ 공공API |
| 지역별 고령·독거노인 분포 | ⭕ 통계청 SGIS |
| 무더위쉼터 (운영시간·유형) | ⭕ 공공데이터포털 |
| 댁내 온·습도 센서 | ⚠️ 응급안전안심서비스 API 스펙 확인 필요. 불가 시 **시뮬레이션** |

### 평가

| 항목 | |
|---|---|
| 강점 | 라스트마일 문제 해결. 하드웨어 불필요. 두 집단 동시 커버 |
| 리스크 | 실제 센서 데이터 접근 불가 가능성 → 합성 데이터로 대체 |
| 해커톤 적합도 | **★★★** |

## 가설 2. 실질 커버리지는 명목의 절반도 안 된다

> **쉼터 커버리지에 정보·시간·진입 필터를 적용하면, 안전하다고 표시된 지역의 상당수가 사각지대로 뒤집힌다.**

### 세 필터

```
전체 쉼터 (9만 3천 곳)
  ↓ ① 시간 필터 — 지금 열려 있는가        (주말 80% 폐쇄, 공휴일 54.6% 미운영)
  ↓ ② 진입 필터 — 내가 들어갈 수 있는가    (71.3% 회원제)
  ↓ ③ 정보 필터 — 존재를 아는가            (모름 33.0%)
  =
실질 이용가능 쉼터  ← 아무도 계산한 적 없다
```

### 검증

선행 논문(서희진·이준우)의 명목 사각지대 **28%**와 직접 비교. 그 격차가 곧 우리 기여.

**기대 산출물 한 장**
> 명목 커버리지 72% → **주말 밤 실질 커버리지 N%**
> 추가로 드러나는 사각지대 고령인구 N만 명

### 평가

| 항목 | |
|---|---|
| 강점 | **데이터 확보 확실**(공공데이터만으로 가능). 결과가 극적. 선행 논문이 한계로 명시한 지점이라 방어 쉬움 |
| 리스크 | **분석 리포트에 그칠 위험.** 서비스 형태가 안 나오면 "그래서 뭘 만들었나" 질문 |
| 해커톤 적합도 | **★★★** (단, 단독으로는 부족) |

## 가설 3. 쏠림은 문제가 아니라 정답이다

> **사람들이 이미 공항·박물관으로 가고 있다면, 그게 잘못된 게 아니라 공식 쉼터가 잘못된 것이다.**
> 실제로 사람이 모이는 곳을 쉼터 네트워크로 편입하면 커버리지가 급증한다.

### 발상

행정이 지정한 쉼터(경로당 중심) vs 사람이 실제로 가는 곳(대형시설·지하철역·도서관·은행·대형마트).

후자는 **24시간 또는 장시간 운영**되고, **회원제가 아니며**, **눈치를 안 봐도 된다.** 미이용 사유 3·4위(시선·공간 불편 19.8%)가 원천적으로 해소된다.

### 검증

비공식 피난처를 포함했을 때 커버리지 상승폭 측정. 특히 **주말·야간에 격차가 가장 크게 벌어질 것**으로 예상.

### 평가

| 항목 | |
|---|---|
| 강점 | **가장 신선하다.** 문제를 뒤집는 서사가 발표에서 강함 |
| 리스크 | 민간시설 협조는 해커톤 범위 밖 → 제안 수준에 머묾. "그래서 실현되나?" 질문 |
| 해커톤 적합도 | ★★☆ (가설 2의 보조 각도로 쓰면 강력) |

## 가설 4. Pull을 Push로 뒤집는다

> **찾아오길 기다리는 구조라서 33%가 모른다. 먼저 보내면 해결된다.**

폭염특보 발령 시 자동으로 **"지금 열려 있는 가장 가까운 곳"**을 개인별로 지정해 발송. 채널은 재난문자·생활지원사·통반장 복합.

### 평가

| 항목 | |
|---|---|
| 강점 | 1위 사유(33%)를 직접 겨냥 |
| 리스크 | **재난문자는 이미 온다.** "폭염주의보 발령, 야외활동 자제" 같은 것. 차별점은 *개인화된 장소 지정*뿐인데 이게 약하게 보일 수 있음 |
| 해커톤 적합도 | ★★☆ (가설 1의 기능으로 흡수하는 게 나음) |

## 가설 5. 이동시키지 말고 집을 시원하게

> **B그룹에게 "쉼터로 가라"는 애초에 틀린 처방이다. 이동 자체를 없애야 한다.**

냉방기 보유·가동 여부와 주거 환경(노후도·단열·최상층/반지하)을 결합해 **에너지바우처·냉방기 지원 우선순위**를 산출.

### 근거

에어컨이 있어도 전기료 부담으로 미가동 → 집이 위험 장소가 된다.

### 평가

| 항목 | |
|---|---|
| 강점 | B그룹에 대한 유일한 정직한 답 |
| 리스크 | **개별 가구 냉방기 보유·전기 사용 데이터 확보가 사실상 불가능.** 해커톤에서 추정으로만 가야 함 |
| 해커톤 적합도 | ★☆☆ |

## 권장 조합

> **가설 2로 문제를 증명하고, 가설 1로 해결한다. 가설 3은 발표의 반전 카드로.**

```
[증명] 가설 2 — 실질 커버리지 재계산
   "선행 연구는 28% 사각이라 했지만, 세 필터를 넣으면 N%다"
        ↓
[해결] 가설 1 — 돌봄 인력용 우선순위 도구
   "그럼 어떻게? 앱을 깔라고 할 수 없다. 이미 매일 가는 사람이 있다"
        ↓
[확장] 가설 3 — 비공식 피난처 편입
   "그리고 사람들이 이미 가는 곳을 인정하면 커버리지가 이만큼 오른다"
```

### 이 조합의 장점

1. **데이터 리스크 분산** — 가설 2는 공공데이터만으로 100% 가능. 센서 데이터가 막혀도 발표는 성립
2. **분석 + 서비스 둘 다** — 리포트로 끝나지 않고, 앱으로만 끝나지도 않음
3. **서사가 이어짐** — 문제 증명 → 해결 → 확장. 발표 3분 구조가 그대로 나옴
