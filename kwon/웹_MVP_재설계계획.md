# 들리는 화면 웹 테스트 MVP 재설계 계획

## 이번 버전의 목표

로컬 브라우저에서 동영상 파일 또는 URL을 입력하고 다음 결과를 확인한다.

```text
사람이 말하지 않는 구간
→ 해당 구간의 시간순 프레임 3장
→ 안정적으로 완성된 화면 글자 또는 장면 설명
→ 실시간 처리 로그와 결과 표
```

TTS와 오디오 믹싱은 이번 검증 범위에서 제외한다. 먼저 gap과 화면 분석 품질을 검증한 뒤 `script.json`을 TTS 입력 계약으로 사용한다.

## 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 웹 UI | Streamlit | 한 명이 로컬에서 빠르게 테스트하고 실행 시 브라우저를 자동으로 열기 쉬움 |
| 파일 입력 | Streamlit upload | MP4/MOV/MKV/WEBM 지원 |
| URL 입력 | yt-dlp | 직접 미디어 URL과 여러 공개 영상 페이지 대응 |
| 미디어 처리 | FFmpeg/FFprobe | 오디오 추출과 특정 시점 프레임 캡처 |
| 음성 탐지 | faster-whisper + VAD | 음악/일반 잡음을 단순 무음으로 오인하지 않고 사람 발화를 중심으로 탐지 |
| OCR/VLM | OpenAI Responses API | 별도 OCR 모델 없이 다중 프레임 비교와 구조화 응답을 한 요청으로 처리 |

## 점진적으로 나타나는 글자 해결 전략

프레임 한 장의 OCR 결과를 바로 채택하지 않는다.

1. 각 gap의 20%, 60%, 90% 시점 프레임을 캡처한다.
2. 세 프레임을 시간순으로 한 번의 Vision 요청에 전달한다.
3. GPT에게 프레임별 글자를 합치지 말고 변화 과정을 비교하도록 지시한다.
4. 뒤쪽 프레임에서 완성된 글자만 `stable_text`로 반환한다.
5. 보이지 않는 글자를 추측하거나 부분 글자를 복원하지 않는다.
6. 글자가 불완전하거나 전환 중이면 `stable_text`를 빈 문자열로 둔다.
7. 안정된 글자가 없을 때만 장면을 짧게 설명한다.

이 방식은 모든 형태의 애니메이션 자막을 완벽하게 해결하지는 않지만, 중간 프레임 한 장만 OCR하는 방식보다 잘린 글자와 합성 오류를 크게 줄이는 MVP 전략이다.

## 데이터 흐름

```text
업로드 파일 또는 URL
        ↓
data/output/<job_id>/source.*
        ↓
speech_audio.wav
        ↓
segments.json
        ↓
frames/gap_000_01.jpg ... 03.jpg
        ↓
OpenAI 다중 이미지 분석
        ↓
script.json
        ↓
웹 로그 + 결과 표 + 프레임 미리보기
```

## 결과 계약

각 gap은 다음 형태로 저장한다.

```json
{
  "id": "gap_000",
  "start": 12.4,
  "end": 16.2,
  "frame_times": [13.1, 14.7, 15.8],
  "stable_text": "3분기 매출 3억",
  "description": "막대그래프가 오른쪽으로 상승한다",
  "narration": "3분기 매출 3억",
  "source": "ocr",
  "confidence": "high",
  "reason": "마지막 두 프레임에서 완성된 문구가 동일하게 보인다"
}
```

`narration`은 다음 TTS 단계에서 그대로 사용할 후보 문장이다.

## 이번 버전의 제한

- DRM 영상과 로그인이 필요한 비공개 영상은 URL 입력으로 처리하지 못할 수 있다.
- 계속 대사가 이어지는 영상에는 해설 후보가 없을 수 있다.
- 노래와 웅얼거림은 VAD가 사람 음성으로 분류할 수 있다.
- URL 기능은 로컬 테스트용이다. 외부에 공개 배포할 때는 다운로드 URL 보안 검증과 작업 큐가 추가로 필요하다.
- 프레임 3장은 이미지 토큰으로 과금된다. 웹에서 최대 분석 gap 수를 제한한다.

## 완료 기준

- `run_web.ps1` 실행 시 로컬 웹 페이지가 열린다.
- 파일 업로드와 URL 입력 중 하나를 선택할 수 있다.
- 말 없는 구간과 시간 정보가 로그에 표시된다.
- 각 gap의 프레임 3장과 OCR/VLM 결과가 표시된다.
- 부분 자막은 완성된 뒤의 문구만 채택하거나 불확실하면 건너뛴다.
- 결과 전체를 `script.json`으로 내려받을 수 있다.
